## 2. NOT IMPLEMENTED CORRECTLY — findings, most severe first

This section preserves the original review findings. The fix pass above and the current-status
section below supersede any item explicitly marked fixed.

### F1 — The client and the backend are two disconnected halves *(blocking)*

The RN app never calls the relay. Verified:

```
grep -rn "v1/atomize|/v1/session/warmup|/v1/eval" apps/mobile/src scripts
→ only scripts/smoke-t0.mjs
```

`backend/relay-py` has a correct, boxed atomizer pipeline that **no client code invokes**.
`apps/mobile/src/runtime/T0FocusSession.ts` has its own `deterministicAtomize()` that never leaves
the device. The `/v1/session/warmup` context pack is served by the relay and consumed by nobody —
`lld/ContextPack.ts` has no production caller either.

Consequence: every backend guarantee (schema-lock, repair-once, cost reservation, `meta.source`
attribution) is unreachable from the product. The smoke test proves the relay works; nothing proves
the product uses it.

### F2 — The running product free-texts steps. INV2 is violated in spirit and in output *(blocking)*

`T0FocusSession.deterministicAtomize()` splits the transcript on `/\s+(?:and then|then|and)\s+|[.;]\s+/`
and emits the user's own words as steps, with `est_min: 3` hardcoded and one constant
`done_signal` for every step. Driven end-to-end:

```
input:  "Do my taxes and then email Sam"
output: step_card 1/2 "Do my taxes"   est_min 3
```

"Do my taxes" is the archetypal *non*-atomic task this entire product exists to break down. It
fails all four clauses of the digest's own atomicity rubric. It also violates the atomizer prompt's
own hard rule — "the FIRST step must be 1 or 2 min" — and `semantic_checks.check_step_atomic` is
never run on this path because that function lives in Python and F1 means it is never reached.

INV2 says "steps are spoken by index, never generated at speak-time." Technically satisfied
(`StepGate` indexes a list). Substantively defeated: the list itself is generated by a regex from
raw speech, with no validation gate between generation and speech.

### F3 — The cognitive plane cannot fire. `CHECK_IN` is unreachable *(blocking)*

`T0FocusSession.applyPolicy()` calls `decide()` with `defaultBeliefs()` (every belief `0.5`),
`defaultRegisters()` (`Focused: 0.5`, every barrier `0`, `Initiating: 0`), `now: 0`,
`session_elapsed_ms: 0`, `execution_stalled_ms: 0`, `step_just_completed: false`.

Against `Policy.evaluateGuards`, **not one guard condition is satisfiable** under those constants.
Every call returns `Observe`. Driven end-to-end:

```
speak -> { state: 'WORKING', step_index: 1, steps_total: 2 }   ← never CHECK_IN
```

`BeliefModel.applyEvidence`, `BeliefModel.decay`, and `EvidenceTiers.decideEvidence` have **zero
production callers** (verified by grep) — they exist only for their own tests. The belief vector is
never fed evidence, so the registers the policy reads are permanently the hardcoded neutral
defaults. Blueprint doc 13 — the deepest document in the set — is implemented as dead code.

Latent second bug in the same function: `interventionHistory.push({ at_ts: decision.refractory_until_ts })`
stores a **future** timestamp in an "at" field. Once beliefs are real, `now - last < window` will
compare against a time that has not happened, and the refractory veto will misfire permanently.

### F4 — A user in a stuck moment loses their plan *(blocking, product-breaking)*

`handleWorkingIntent` routes `crew_reatomize` to `firstStepFromTranscript(transcript)` — where
`transcript` is the *stuck utterance*, not the task or the current step. Driven end-to-end:

```
stuck#1 widgets=[1/2 "Do my taxes"]  speech="Stay with this: Do my taxes"
stuck#2 widgets=[1/2 "Do my taxes"]  speech="Stay with this: Do my taxes"
stuck#3 widgets=[1/1 "I am stuck"]   speech="Start with: I am stuck"
```

The third "I'm stuck" deletes the user's step list and replaces it with a single step reading
**"I am stuck"**, which the orb then reads back as an instruction. For the target user, at the exact
moment of executive-function failure, this is the worst reachable behaviour in the product.

Secondary: `stuckCount` is incremented *after* `route()` is called, so the threshold fires on the
third stuck rather than the second. The digest says `stuck_count >= 2`.

### F5 — Non-ASCII speech is destroyed *(blocking for the stated market)*

`transcriptFromBytes`/`bytesFromText` use `String.fromCharCode` and `& 0xff` — Latin-1 truncation.

```
input:  "मुझे टैक्स भरना है"
output: step_card 1/1 ".AG HM8 -0(> 9H"
```

The blueprint's differentiator is code-mixed Indic speech (Sarvam Saarika, 22 Indian languages,
WER ≤18% Hinglish). The transport path mangles it before any of that matters. `IntentClassifier`
and `EvidenceTiers` are also English-regex-only, with no Hinglish rules and no ADR recording that
as a Phase-1 narrowing.

### F6 — The cost reservation is a no-op in the shipped path *(high)*

`backend/relay-py/src/orb_relay/app.py:28` — `_rates = Rates()`. Every rate field defaults to `0`.
`price_paise()` therefore returns `0` for every spend, `remaining_paise` never decreases, and
`ReservationExceededError` can never be raised in the running relay. Non-zero `Rates` appear **only
in tests** (`test_cost_meter.py`, `test_app_routes.py`). There is no config path that reads real
prices.

INV5 and C12 are tested and unwired. This is the textbook shape of a green-but-meaningless guard.

### F7 — The user pause and the OS interrupt have been collapsed into one path *(high)*

`T0FocusSession.pauseEnvelope()` dispatches `os_interrupt` for a **user-initiated** pause, and
`makeEnvelope` then emits `bed.gain_db: -60` for `INTERRUPTED`.

Blueprint 02 §5.1/§8 and digest §5 spend an entire section separating these: a *user-intent* pause
stops the bed, releases the mic at OS level, and requires an explicit resume; a *transient* OS
interrupt keeps context and ramps the bed back within 300 ms behind a cover. `InterruptionHandler.ts`
exists precisely to make that call — and has **zero production callers**. Both paths now land in
`INTERRUPTED` at −60 dB, which reads as "bed silent on a transient interrupt", i.e. INV1's recovery
contract is inverted.

`pauseContractSteps()` — the five ordered steps including "mic released before the UI claims it
isn't listening" — is never executed.

### F8 — `advanceFromNext()` writes session state outside the FSM *(high)*

```ts
state = 'STEP_PRESENT';   // T0FocusSession.ts, advanceFromNext()
```

A raw assignment bypassing `dispatch`. The `next` intent therefore never passes through `STEP_DONE`
and never consults `has_more_steps`; the last-step case is guarded by an ad-hoc `gate.isLastStep`
check instead. "The control path is deterministic" means *one* writer of state. There is now a
second.

### F9 — `meta.source` carries a false provenance claim *(medium)*

Every envelope `T0FocusSession` produces is stamped `source: 'reuse'`, including the
regex-split path. Digest §2 makes `meta.source ∈ {cache_hit, reuse, model}` mandatory and §6 has the
eval harness track fallback-rate *from this field*. Labelling a local regex split as "reuse" means
the one observability channel for degradation reports the healthiest possible value at all times.

### F10 — `IntentClassifier`'s doc comment contradicts its body — LESSONS L7, recurring *(medium)*

The comment says "Order matters: `done` is checked before `next` so 'done, next one' resolves to
`done`". The body does not first-match-win — it collects **all** fired labels and requires exactly
one, else returns `matched: false`. So "done, next one" fires `done` + `next` → ambiguous →
`AmbiguousIntentNotWiredError`, which nothing wires. Common ADHD utterance shapes ("done, what's
next?") fire three labels and throw.

`LESSONS.md` L7 logs this exact class of defect *in this exact file* and marks it RESOLVED. It is
resolved for negation and substrings; the ordering claim is a fresh instance of the same mistake.

### F11 — `boundary-lint` originally missed backend/provider surfaces *(medium; provider part fixed)*

```js
CHECKED_DIRS = [
  'apps/mobile/src',
  'backend/gateway-sidecar/src',
  'backend/relay-py/src',
  'backend/relay-rs/src',
]
```

C9's "one model door" was originally enforced over TypeScript only. This is fixed for the current
tree: provider-import lint now walks the mobile app, gateway sidecar, Python relay, and Rust relay.

Residual gap: generic plane-barrel isolation is still not implemented. The current documented lint
scope is intentionally narrower: presence may not import cognitive or voice.

### F12 — Dead modules, confirmed by grep *(fixed for the named T0 composition set)*

At original review time there was no production caller outside each module's own tests for
`BeliefModel.applyEvidence`, `EvidenceTiers.decideEvidence`, `InterruptionHandler`, `DuckingMixer`,
`ColorMorph`, `ContextPack`, `ClarifyProtocol`, `phrasers.py`, and `observability/metrics.py`.

The current tree composes those modules into `T0FocusSession`, `VoiceLoopController`, `AudioGraph`,
`App.tsx`, the relay warmup route, and eval aggregation. Remaining work is live provider/device
evidence, not lack of T0 call sites.

## 3. EVALS — the blueprint's #1 quality claim is not fully implemented

`AGENTS.md` correctly states: *"Evals are voice-to-voice. Text-only metrics are not proof for
audible quality claims."* The local `eval/` module now owns the full-size deterministic T0 replay
suite, but it still does not prove live provider audio quality or physical-device audibility.

| Digest §6 requires | Repo has |
|---|---|
| voice-to-voice N=200, stratified by accent/language/ADHD-speech-pattern/acoustic condition | 200 deterministic T0 voice replay cases with latency, silence, loudness, accent, and acoustic-condition metadata |
| atomizer goldens N=300 | 300 deterministic cases expanded from checked-in ADHD seed fixtures and scored through the real schema validator |
| consistency K=10 × N=200 | 200 deterministic K=10 replay cases; `step_count_mode_agreement` must pass instead of being hardcoded |
| intent classifier, 500 utterances | 500 deterministic utterance replays scored through `_safe_intent` against the shared `apps/mobile/src/shared/intent-rules.v1.json` rule contract |
| belief calibration, ~5,000 labeled windows | 5,000 deterministic replay windows with Brier-score and coverage gates |
| 11 named CI gates | Covered locally by explicit voice, atomizer, consistency, classifier, schema, audio-suite, latency-harness, belief, policy, and cost metrics |

The local replay corpus now reaches the Phase 1 count targets without storing a massive generated
JSON file.

Two things must be said fairly. First, the code is honest about it — `evidence.claim_boundary`
reads *"T0 replay expanded deterministically from checked-in seeds; live provider and device audio
proof remain separate"*, and `domain/README.md` says the same. That honesty is the right instinct
and it is why this is a device/provider evidence finding, not a local-gate defect. Second,
`/v1/eval/metrics` correctly refuses caller-supplied observations (422) and fails closed on missing
metrics.

But deterministic replay is not the live voice-to-voice proof the blueprint asks for. The current
implementation is honest local T0 evidence, not final live quality evidence.

## 5. AI SLOP — the specific patterns

To be precise about the term: this repo has *far less* slop than typical. Comments mostly earn
their keep and several explain genuinely subtle choices. The slop that exists is of one kind —
**prose asserting a rigor the code does not have** — and it is concentrated:

1. **Historical comments described unimplemented algorithms** — `IntentClassifier`'s ordering claim
   (F10) and `boundary-lint`'s barrel rule (F11). The current classifier body and lint comments now
   match their actual behavior.
2. **Replay is not live proof** — `gates.py` now has full-size deterministic replay lanes, but those
   lanes use generated T0 observations. They must not be cited as live provider or physical-device
   audio quality evidence.
3. **Spec citation as proof of compliance.** Nearly every file header cites `§2`/`§4`/`INV5`. In the
   dead modules (F12) the citation is the *only* connection to the product — the module implements
   the paragraph and nothing calls the module. Citing the spec is not satisfying it.
4. **Doc/manifest drift risk remains review-sensitive.** `AGENTS.md` no longer claims the complete
   eleven-gate corpus or generic plane-barrel lint, but every future manifest/doc change needs the
   same evidence check.

## 10. 2026-08-05 — "will it work end to end with real keys?" audit, two real bugs found and fixed

Traced the live voice path (not just unit tests) and found the composition-layer failure recurring
— two real bugs that would have surfaced on the very first spoken utterance, neither caught by any
of the individually-green build slices because none of them owned the cross-cutting file where the
bug actually lived.

**Bug 1 (critical) — every utterance processed twice, first pass on garbage.**
`VoiceLoopController.handleAudioFrame`'s local-VAD end-of-turn branch called `completeTurn('vad',
'')` synchronously, which fell back to decoding raw mic PCM bytes as UTF-8 text
(`textFromBytes(turnAudio)`) — a leftover from a pre-real-audio T0 era where "audio bytes" were
literally typed text. The real transcript from the relay's STT provider then arrived moments later
and triggered `completeTurn` a second time. Result: two responses per utterance, the first one
nonsense, a wasted paid LLM call on garbage, and session state (step index, stuck-count, turn seq)
advancing twice for one turn.

**Fix:** local VAD end-of-turn now only signals `relay.endOfTurn()` and returns — it never calls
`runtime.acceptAudio` itself. The turn completes exactly once, when the real transcript arrives via
`handleTranscript` (triggered by `RelayClient.onTranscript`). `completeTurn` also no longer
re-signals `endOfTurn()` when it's already running because the final transcript just arrived (was
a wasted extra provider call). `textFromBytes` and the now-dead `utf8Decode` import are removed.

**Bug 2 (high) — TTS audio would likely play as noise or clicks, not speech.**
All three real TTS backends (Fish, Sarvam, Cartesia) request or return WAV-container audio; the
sidecar chunked those bytes directly with no header stripped, and the client
(`RelayAudioPlayer.ts`) assumes raw headerless PCM. The 44+ header bytes would play as if they were
the first ~22 audio samples (audible click), and if a provider silently returned a compressed codec
instead of the requested WAV (flagged as a real risk for Fish specifically), the whole clip would
decode as noise.

**Fix:** `wav.ts` gained `extractPcmFromWav` — walks the real RIFF chunk list (not a hardcoded
44-byte offset, since some encoders insert a metadata chunk before `data`) and strips the container
before chunking. Returns bytes unchanged (not corrupted) when the input isn't a well-formed WAV, so
a provider that returns something else degrades to "still wrong, no worse" rather than "worse."
Logs a warning when a non-fake backend returns something that doesn't parse as WAV at all — that
case is a real, still-unverified-until-a-live-key format mismatch this fix cannot resolve by itself.

**Verification, both fixes:**
- Regression test in `VoiceLoopController.test.ts` simulates the actual async server round-trip
  through the real `RelayClient` (not a shortcut) — asserts local VAD end-of-turn produces zero
  atomizer calls, and the atomizer fires exactly once, with the correct text, only after the
  simulated server transcript arrives.
- 6 new tests for `extractPcmFromWav` — round-trips through this repo's own `pcm16ToWav`, handles a
  metadata chunk before `data`, and safely no-ops on non-WAV/malformed/fake-fixture input.
- Fresh `npm run verify`: 350/350 vitest, 71/71 pytest, 24/24 cargo, exit 0.
- Fresh `npm run android:build:check`: BUILD SUCCESSFUL.

**Still true after this fix:** giving the app real keys makes it boot and make real network calls,
but the per-provider field-name/format confidence notes in `backend/voice-provider-sidecar/src/{stt,tts}/*`
remain unverified against a live key — that's the next real gap, not a fabricated "done."
