# Lessons — recurring mistakes, logged once, never repeated

Every Opus review verdict appends here when it finds a mistake. Before opening a new worktree, read
this file. A second occurrence of a logged mistake is a review failure, not a fresh finding — the
reviewer should have caught it from this list.

| # | Mistake | Where seen | Rule now enforced |
|---|---|---|---|
| L1 | **An all-optional context object read with `?? default` turns a caller's missing field into a silent wrong answer.** `GuardContext`'s fields are all optional; `has_more_steps` defaulted to `(0, 0)`, so `0 < 0 == false` sent an under-populated `step_advance` straight to `SESSION_DONE` — a caller that forgot to fill the context would silently end the session and let the bed go quiet (INV4, and INV1 via `BedOptionalState`). Fail-*safe* defaulting only works where "guard false" is a no-op; on a branching decision every default is a real destination. | `session/StateMachine.ts` `evaluateGuard`/`dispatch` (Tier 1–2 review, 2026-08-04) | Branch-shaped edges assert their guard inputs (`MissingGuardContextError`) instead of defaulting; unlisted branch guards throw by default so the next author must opt in. **Tier 6 `Policy.ts` is the repeat risk**: `decide(beliefs, session, history)` has a far larger optional-context surface, and a veto that defaults to `false` is an intervention firing that should have been suppressed (INV6/INV7). Give `Policy.ts` required inputs, not optional ones with defaults. |
| L2 | **A green unit suite that only feeds well-formed inputs proves nothing about fail-closed behaviour.** 85 tests passed while the single most dangerous input (an empty `GuardContext` on the session-ending branch) was untested. The suite tested every edge the diagram draws and no edge the caller might mis-dispatch. | `session/StateMachine.test.ts` (Tier 1–2 review, 2026-08-04) | Every guarded/branching pure function needs at least one missing-field and one malformed-field case alongside its happy path. Reviewers drive the reducer themselves (AGENTS.md invariant 7) — "85 tests green" is the floor, not the evidence. |
| L3 | **A spec table written as prose can contain rows that are unreachable if transcribed as a top-to-bottom if/elif chain.** BUILD-DIGEST §2's router table lists `state==INTAKE → CREW.atomize` *after* four intent rows that already partition the closed 6-member `IntentLabel` union — transcribed literally, the INTAKE row is dead code, and a brain-dump containing "stop" or "what" would mis-route to `pause_session`/`fast_voice` mid-intake. | `router/Router.ts` (Tier 1–2 review, 2026-08-04) | Check every spec-table row for reachability before transcribing; where a row is shadowed, reorder and say why in a comment rather than emitting dead code or silently dropping it. **Tier 6 repeat risk**: §2's policy CANDIDATE GUARDS block is explicitly *not* first-match ("all evaluated, least-intrusive-that-fired wins") while the HARD VETOES block above it *is* ordered — transcribing both the same way is the bug waiting to happen. |
| L4 | **The money rule got applied to a quantity that is not money.** `AGENTS.md` invariant 6 ("money is integer paise, never float") was enforced via `assertIntegerPaise` over all four `UsageDelta` fields, including `stt_seconds_billed` — a duration that real STT providers bill fractionally. The error message also says "paise" about a field that is not paise. | `session/CostReservation.ts` (Tier 1–2 review, 2026-08-04) | Invariant 6 governs *currency* fields. Usage quantities get their own rule: integer where the unit is inherently discrete (tokens, chars), non-negative-finite otherwise. Flagged in-file as a KNOWN SEAM for Tier 7 `CostMeter.ts`, which must resolve it before wiring a real provider. |
| L5 ✅ RESOLVED at Tier 5 (2026-08-04): schema extracted to `apps/mobile/src/shared/atomizer-schema.ts`; the only remaining mirror is cross-language (pydantic in `backend/relay-py/.../schemas.py`, which is where validation actually runs) and is documented as hand-synced with a generate-from-JSON-Schema trigger if a third language appears. | **"Duplicate now, extract on the third consumer" needs the third consumer counted against the build plan, not against today's diff.** `AtomizerStep`/`AtomizerOutput` were duplicated across the RN/relay tsconfig boundary following the `BeliefName` precedent — correct for this diff, but BUILD-DIGEST §8 already names three consumers ("step gate, context-pack reuse format, clarify-protocol slot-filling — any change to it is breaking across three modules at once"). | `session/StepGate.ts` (Tier 1–2 review, 2026-08-04) | The extraction trigger for the atomizer schema fires at **Tier 5** (`ContextPack.ts` + `ClarifyProtocol.ts`), not "someday". Whoever builds Tier 5 extracts a shared contracts package and deletes the copies — do not add a third hand-maintained copy. |
| L7 ✅ RESOLVED in T0 replay (2026-08-04): `containsKeyword` is now word-aware, negated completion fails closed, and both cases are covered in `IntentClassifier.test.ts` plus `domain/evalsets/t0-contract-corpus.v1.json`. | **A doc comment that describes behaviour the body does not implement is worse than no comment.** `containsKeyword` was documented as a "word-boundary-ish match [that] avoids 'stuck' matching inside 'unstuck-ify'"; the body was a bare `.includes()`, which did exactly the thing the comment claimed it avoided. The comment was the only thing standing between the reader and two live defects — substring false positives (`'however'.includes('how')`) and **unhandled negation, which lands directly on INV3**: "I'm not done yet" fired the `done` rule and fed `intent_done`, inferring a completion the user explicitly denied. | `router/IntentClassifier.ts` (Tier 1–2 review, 2026-08-04) | Comments assert what the code does, never what the author intended it to do. Keep negation/substring cases in every classifier replay set; do not wire a model fallback that can override explicit negation into completion. |
| L6 | **A pure reducer that takes its own resume target from the caller cannot enforce the invariant it looks like it enforces.** `dispatch(INTERRUPTED, 'os_resume', {prior_state})` returns whatever state the caller supplies, unvalidated — including `STEP_DONE` or `SESSION_DONE`. This is *correct* here (resume must restore a state already reached legitimately) but means INV3/INV4 are enforced only on the forward edges; a caller bug can launder any state through resume. | `session/StateMachine.ts` `resume_prior` (Tier 1–2 review, 2026-08-04) | The FSM owns forward-edge enforcement only. `InterruptionHandler.ts` (presence plane) owns `interrupted_from` and must be the single writer of `prior_state`; its review must check that it never synthesises a resume target. Recorded so Tier 3+ callers do not assume the reducer is validating this for them. |
| L8 | **Injecting a dependency makes the logic testable and the *transport* untested.** Every atomizer test injected a `GatewayClient`, so 34 tests were green while an unreachable sidecar produced an unhandled `httpx.ConnectError` — a raw 500 with a stack trace where a typed 503 belonged. The seam that makes the unit tests clean is exactly the seam they stop covering. Found only by starting the real server and calling it with no sidecar running. | `proxy/gateway_client.py` (backend build, 2026-08-04) | Every injected-transport boundary needs one test that exercises the *real* implementation against a failing transport, not just the fake. AGENTS.md invariant 7 (drive the thing, don't trust the suite) is what caught this; treat a green suite over an injected seam as evidence about the logic only. |
