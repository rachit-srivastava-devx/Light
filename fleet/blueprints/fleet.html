A from-scratch fleet-* Rust workspace, migrated by extracting the proven parts of the existing fleet system and building only what was genuinely absent. Sixteen independent packages behind a one-directional dependency DAG, each blueprinted to be hand-codeable, built by Sonnet agents, and reviewed adversarially — distrusting the tests.

01The decision — iterate, don't rebuild

Three parallel audits established that the existing fleet system already builds and passes, with the hard, risky parts coded and adversarially tested: an fd-3 worker protocol, a blake3 hash-chained tamper-verified ledger, worktree isolation, keyless CLI-driving, a type-state lifecycle with compile-fail tests, and a mutation-gated quality ratchet. Fleet's target design is the same doctrine redrawn with cleaner crate boundaries — a refactor target, not a new system. So: extract the working modules into clean ≤80-line crates, and build fresh only the crates fleet lacked (ingress, ambiguity-scan, hybrid code-context, unified egress, the memory bandit).

04The doctrine it holds

T1 · two planes

A deterministic Rust control plane decides everything and never calls an LLM; CLI workers only propose, over fd 3.

T2 · re-run every check

The kernel re-derives; a proxy is not the property. Denominators refuse an empty measurement.

T3 · one event log

Everything is an append-only, blake3 hash-chained event; tamper is detected on the chain walk.

T4 · no daemon

Spawn-on-demand, exit-when-done. Ingress polls; the dashboard is a per-run localhost server or a zero-server file tail.

T5 · keyless

No API keys. Cost = estimated tokens + rate-limit-window %, metered on real tokenizer counts, never a dollar bill.

hermetic

A worker gets its skills / MCP / prompt from the repo .fleet/, with env_clear() + HOME/XDG overridden — never the user's ~/.claude.

05Open — needs human judgment, not tests

The keyless thesis itself. fleet-worker::probe_no_ambient is implemented and unit-tested, but whether claude/codex genuinely run keyless-isolated — or leak ambient credentials (keychain, a background daemon socket) that env_clear()+tempdir can't block — cannot be settled by a test. It needs one real run against the CLIs and a human call. Everything downstream rests on this.

Lifecycle state mapping. fleet-plan's map from the historical review.sh states to fleet_types::LifecycleState is a best-fit guess; confirm it when wiring the composition root, or submission_eligible/verdict_decision may gate at the wrong points.

Deferred, on purpose. Code-context embeddings (behind the VectorIndex port — ort never stabilised); fleet-store's vec0 vector path (unverified until a vec0 extension is installed); Restate (replaced by an on-disk step-log with the same crash-resume property); and several fleet-cli aux subcommands (Pr/Attest/Freeze/Contract/Console/Skills/Mcp) that parse but return a typed NotYetImplemented.

Dependency watch. fleet-events's imap pulls imap-proto, which emits a future-incompat warning; and rank-fusion was dead (yanked) so RRF is hand-rolled. Neither blocks today.

06What the adversarial review earned

Reviewing by distrusting the tests — reproducing each crate and killing a mutant by hand — caught what green suites hid:

  • A production corruption path in fleet-govern: the settle id-check was under-tested (the existing test left the reservation list empty, so the comparison never ran). Neutering it passed all 14 tests. A pinning test now kills that mutant.
  • A proxy-not-property test in fleet-worker: the hermetic test first checked HOME's value — which .env("HOME") sets regardless of env_clear(). The real property is that a non-allowlisted sentinel var never reaches the child. Fixed and re-confirmed.
  • Two latent bugs in fleet-crew (a negative log-floor trivially passing; a non-UTF-8 transcript byte crashing metadata read) — fixed with named tests before they shipped.
  • A dead crate and a never-stabilised one routed around before they became load-bearing.

Every lesson is recorded in blueprints/MIGRATION-PLAN.md §7 so fleet doesn't repeat them.
