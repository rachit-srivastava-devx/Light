# The Lifecycle Is the Diagram

This edition is an implementation atlas, not a poster. The first A1 page carries one complete lifecycle graph; the following pages expand each block into an atomic control, data, and evidence flow. A CTO can read the whole system in one pass, while an engineer can follow the same node into schemas, idempotency keys, failure branches, recovery actions, tools, source links, and pricing units.

The visual system follows the DevX doctrine: white paper, black editorial type, one electric-blue accent, sharp square geometry, and a strict grid. Red is reserved for fail-closed or human-authority boundaries; green marks verified Fleet behavior or durable evidence. There are no gradients, shadows, decorative icons, or rounded SaaS cards. Dense material is split across pages so hierarchy remains legible at print scale and under digital zoom.

Evidence boundaries are part of the language. Vendor-documented behavior is labelled DOC, target architecture is PROPOSED, current Fleet behavior is LIVE, and incomplete capability is PARTIAL. This is essential for Sourcegraph SCIP: the vendor path is drawn separately from the enterprise Temporal and Kafka control plane, preventing a convenient but unsupported arrow from becoming an architectural claim.

Autonomy is shown as a deterministic state machine, not permission handed to a model. Agents discover, clarify, plan, implement, review, and repair. External policy, protected merge and deployment controls, cryptographic evidence, and named humans retain irreversible authority. Graph and vector stores are identified as rebuildable projections, while source systems, PostgreSQL command state, and immutable object evidence remain authoritative.

The final pages make the design falsifiable. Pricing is expressed in public units rather than invented total cost, open-source tools show infrastructure and operations as the actual cost, and custom-sales gaps remain explicit. The acceptance page turns source completeness, multi-repo consistency, retrieval isolation, SLO capacity, disaster recovery, and Fleet production readiness into tests that can reject the system.
