## M7 — 2 of 3 hits are test-module literals; 1 is real (scoped out)

M7 extracts every `Some("…")` from `keel/fleet/src/main.rs` and requires each non-exempt token to
appear in `--help`. Three tokens failed. Ground truth in the source:

- `Some("builder")` at `main.rs:4218` and `:4247`, and `Some("not-a-real-role")` at `:4227`, are
  **all inside the single `#[cfg(test)]` module** (which starts at exactly `main.rs:4166`; only one
  `#[cfg(test)]` exists, confirmed by `grep -n`). They are argument literals to
  `resolve_run_agent(...)` *test calls* — e.g. `match resolve_run_agent(None, Some("builder"),
  &state, false)` — not dispatch arms; `builder` is a role name in the roles array (line ~3250),
  not a command. Compile-time unreachable from `--help`, so not discoverable by design.
- `Some("contract")` at `main.rs:144` is a **real dispatch arm** (`contract_command` at `:3143`)
  with no `--help` line — a genuine present-but-hidden command. It belongs to S2's uncommitted
  `main.rs` (`fleet contract` was built there), so adding its help line is S2 territory; **scoped
  out** as B17 item 2 below.

Fix: M7's extraction now stops at the first `#[cfg(test)]` line — an input filter only:
`awk '/^#\[cfg\(test\)\]/{exit} {print}' ... | grep -oE ...`. Predicate, exempt set, and the
"measuring nothing is a failure" guard are unchanged. Live result:
`M7: reachable but absent from --help: fleet contract`, `24 of 25` rc=1 — both false positives
cleared, the real one still caught. Because M7.sh is hash-covered, `bin/detector-integrity.sh

## T6 — REAL, scoped out (entangled file)

T6 flags `sed -i ''` as BSD-only (won't survive Linux CI). Verified it is REAL with a definitive
measurement: GNU sed 4.10 installed via `brew` (`gsed`), same command shape as the trip points —
`gsed -i '' "s|...|...|" file` → `rc=2`, `gsed: can't read s|...|: No such file or directory`,
file NOT edited; the stock BSD `sed` on the same machine does the same line correctly (rc=0).
GNU treats `''` as the (empty) script and the next word as the input filename; a shell `$ID`
substitution does not rescue it. So on Linux, `bin/codex-fanout.sh:43,107` and
`bin/codex-tick.sh:43` would silently stop marking BACKLOG items in-progress/[x] — exactly the
silent-bookkeeping-defect class this repo exists to catch.

Why not fixed here: a uniform one-word fix (`sed -i ''` → `perl -pi -e`) across all three lines
would be trivial, **but `bin/codex-fanout.sh` currently carries another lane's uncommitted edits**
(`FLEET_WORKER_CLI` for the S-lanes), and git stages whole files — fixing fanout means committing
that lane's work. **Scoped out as B17 item 3 below** with the exact recipe. `bin/codex-tick.sh` is
left untouched too so the three-hit set stays uniform for whoever lands the fanout file.
