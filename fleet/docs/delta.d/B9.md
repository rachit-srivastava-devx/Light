already guarded and "tested in four directions" (free path installs, own-binary installs, a
foreign script refuses, `--uninstall` on a foreign symlink exits 7 and leaves it alive), with the

Standing law observed: *a proxy is not the property*. The backlog's prose was not trusted as fact

## Verification of the backlog's claim (real runs, not read-and-agree)

Four fixtures were built in a scratch dir (`.scratch-b9/`, never committed — deleted before this
tick finished) with a minimal stand-in `keel` crate (prints the exact `--help` marker string

added, actually created `~/.zfunc/_fleet` on the real machine; it was found and removed
immediately (confirmed empty again with `ls`) before any further testing.

1. **Free path installs.** `FLEET_BIN_DIR` pointed at an empty temp dir → `./install.sh` → exit 0,
   binary installed. Matches the claim.
2. **Own binary already installed.** Re-ran the same install against the now-populated bin dir →
   exit 0, `UNCHANGED binary already current` (recognised via the `--help` marker, not refused).
   Matches the claim.
3. **A foreign script refuses.** Pre-populated the bin dir with a plain, non-`fleet` executable

   compared). Matches the claim, **in that layout**.
4. **`--uninstall` on a foreign symlink exits 7 and leaves it alive.** Pre-created a symlink at the
   bin path pointing at an unrelated, nonexistent path (`/nonexistent/some-other-fleet-repo/fleet`,
   standing in for "a different `fleet` repo") → ran `./install.sh --uninstall` → exit 7, refused,
   `readlink` identical before/after. Matches the claim.

**All four of the backlog's described behaviors were confirmed real**, not merely read and
believed.

## A real defect found while constructing the fixtures (not in the backlog's four)

Building fixture 3 a second way — with `FLEET_BIN_DIR` nested *inside* the fixture's own
`ROOT_DIR` (a layout that arises naturally the moment a self-contained test fixture puts
everything, including the fake bin dir, under one scratch root) — **the same foreign script was
silently installed over**: exit 0, and `shasum -a 256` differed before/after. Real output from that
run, against the as-found code:

```
EXIT=0
before=8d0ad4fa7543bb1d09d2d8a5473d3100def7ae4ced53002841b99eca02142f19
after=cb016623e053573b6162e989b531c0b535863216fd7e41a2ebd0cb32bf59cbd6
UNTOUCHED: NO -- CLOBBERED
```

**Root cause**, in `foreign_bin()` as it existed before this tick:

```bash
foreign_bin() {
    [[ -e "$BIN_PATH" || -L "$BIN_PATH" ]] || return 1
    local real; real="$(cd "$(dirname "$BIN_PATH")" && pwd)/$(basename "$BIN_PATH")"
    [[ -L "$BIN_PATH" ]] && real="$(readlink "$BIN_PATH")"
    case "$real" in "$ROOT_DIR"/*) return 1 ;; esac
    [[ -L "$BIN_PATH" ]] && return 0
    "$BIN_PATH" --help 2>/dev/null | grep -q 'frozen, attested change' && return 1
    return 0
}
```

For a **plain file** (not a symlink), `real` is set to `$BIN_PATH`'s own canonical path — the
`case ... "$ROOT_DIR"/*` test then asks "does `BIN_PATH` itself sit under `ROOT_DIR`?", which says
nothing about who put the file there or what it is. The `$ROOT_DIR`/* prefix test is only a
meaningful ownership signal for a **symlink** (does the symlink resolve into our own source tree?).
Because the check ran unconditionally, any plain foreign file sitting under a `BIN_DIR` that
happens to be nested inside `ROOT_DIR` was classified "ours" and installed over without ever
reaching the `--help` marker check — the exact clobber the backlog describes, just gated on
directory layout instead of file identity. In real deployment `BIN_DIR` defaults to
`~/.local/bin`, never nested under the repo, so this did not manifest in the backlog's original
four fixtures — it is a real, narrower gap the described tests did not cover, found only by
actually constructing them a second way.

## Fix (install.sh, `foreign_bin()` only)

```bash
foreign_bin() {
    [[ -e "$BIN_PATH" || -L "$BIN_PATH" ]] || return 1
    # A symlink is ours only if it resolves into this repo's own tree (e.g. a dev symlink into
    # our own build output). The path-prefix test is meaningless for a plain file -- comparing
    # BIN_PATH's own location to ROOT_DIR says nothing about who put it there or what it is, and
    # doing so let a foreign plain file sitting under a BIN_DIR nested inside ROOT_DIR bypass the
    # --help marker check entirely and get silently overwritten. So a plain file is judged ONLY by
    # content (the --help marker), never by where it happens to sit.
    if [[ -L "$BIN_PATH" ]]; then
        local real; real="$(readlink "$BIN_PATH")"
        case "$real" in "$ROOT_DIR"/*) return 1 ;; esac
        return 0
    fi
    "$BIN_PATH" --help 2>/dev/null | grep -q 'frozen, attested change' && return 1
    return 0
}
```

A plain file is now judged **only** by the `--help` marker, never by its location. A symlink is
judged only by where it resolves. Re-ran the nested-`BIN_DIR` fixture 3 against the fixed code:

```

before=8d0ad4fa7543bb1d09d2d8a5473d3100def7ae4ced53002841b99eca02142f19
after=8d0ad4fa7543bb1d09d2d8a5473d3100def7ae4ced53002841b99eca02142f19
UNTOUCHED: yes
```

Re-ran all four original (non-nested) fixtures against the fixed code too — all four still pass
exactly as before (fix is additive-safe, no regression on the described behaviors).

## Self-assessment (do not grade your own work)

The fix narrows the plain-file path to a single signal (the `--help` marker string). That signal
is itself a soft one: a foreign binary that happens to print the literal string
`frozen, attested change` somewhere in its `--help` output (however unlikely) would still be
misclassified as "ours" and overwritten. This was true before this tick as well (the marker check
already existed on the same line) and is unchanged by this fix — this tick closes the
path-comparison bypass, not a hypothetical stronger identity check (e.g. a build-time signature).
That would be a larger change than the backlog asked for.
