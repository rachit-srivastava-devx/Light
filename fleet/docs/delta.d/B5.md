# B5 — REPL parity handover

The expected surface was a Claude-like prompt: enter text, see a plan before side effects, use
history and ordinary terminal editing, interrupt work, watch output arrive, and receive a useful
answer when a command or prompt does not match. The existing screen already had a ratatui layout,
persisted slash-command history, slash completion, streamed reader threads, and nearest-match
messages, but the terminal behavior had three correctness gaps.

## Findings and disposition

1. **[FIXED] Streamed output could lose its tail.** `drain_operation` finalized as soon as the
   child reported an exit status. The stdout/stderr reader threads could still have unread bytes,
   so a fast command could finish with output absent from the transcript. The cost was silent loss
   at the exact boundary where an operator decides whether work completed. Operations now carry an
   explicit close event for each stream and remain live until the child has exited *and* both
   streams have reached EOF.

2. **[FIXED] Ctrl-C was ignored while a plan was waiting for confirmation.** Ctrl-C cancelled an
   active child and cleared an idle input line, but a rendered plan accepted only Enter, `e`, or
   Esc. The operator could not use the familiar interrupt key after submitting a natural-language
   prompt. Ctrl-C now cancels the pending plan, clears the executable queue, and reports that no
   command was run.

3. **[FIXED] The prompt was a hand-rolled append/backspace editor.** Left/right, Home/End, Delete,
   insertion in the middle of a line, Unicode-safe cursor movement, and cursor-aware history were
   missing. The cost was repeated retyping and a visibly worse daily loop than Claude. The existing
   crossterm/ratatui screen is retained for UI parity, with deterministic cursor/edit behavior
   stitched into its event boundary. A full rustyline/reedline takeover was rejected for this
   slice because it would replace the current full-screen renderer; that is a separate integration
   decision.

4. **History was not wholly missing, but it is narrower than Claude.** The current implementation
   persists slash commands and confirmed natural-language plans and supports Up/Down. A plan that
   is refused or cancelled is intentionally not persisted because the current safety contract
   keeps history persistence after confirmation. This remains a parity gap, not one of the three
   fixes in this slice.

5. **Slash commands and unmatched prompts already had useful coverage.** Tab completion exists for
   the documented slash commands; an unknown slash command names the nearest command; and an
   unmatched natural-language prompt refuses rather than guessing while listing close intents.
   These were verified as existing behavior and were not changed in B5.

## Proof

The three fixes have assertions in `keel/fleet/src/repl.rs` unit tests:

- `completed_child_waits_for_stream_eof_before_dropping_tail`
- `ctrl_c_cancels_a_pending_plan_before_execution`
- `line_editing_keeps_cursor_and_history_consistent`

The repository rule forbids editing `tests/acceptance/*`; therefore no acceptance fixture was
modified. The required acceptance-level verifier remains the final proof boundary.

## Verification boundary

REPL tests. `FLEET_MUTANTS=0 bash verify.sh` reached **14 passed, 1 failed, 1 skipped
(denominator: 16)**: the only failed stage was `corpus`, where S9/T15/T1/T20/C1/T5/C11 hit the
30-second detector timeout while multiple other agents were running the same corpus on this shared
checkout. This is recorded as red evidence, not a green B5 claim.
