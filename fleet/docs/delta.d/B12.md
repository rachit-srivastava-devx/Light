# B12 — M6 taught to recognise a truthfully-negated command mention

Backlog item: `handover/BACKLOG.md`, `## [ ] B12 — M6 false positive on a correctly-negated
command`.

**What was left open** is B12's own second, harder half — the design smell the backlog names
explicitly: *"This is the sixth time a detector has fired on documentation about what it watches
(T6, B10, T20, A8, M6)."* Relying on every doc author remembering the backtick-means-exists
convention is exactly the discipline problem the backlog says is not the real bug — the detector
itself should be able to read a sentence that explicitly negates the claim it is backtick-quoting,
regardless of which punctuation a future writer reaches for. That is the actual defect fixed here.

## The fix — `tests/corpus/M6.sh`

Restructured the command-extraction loop from "collect every backticked `` `fleet <cmd>` `` across
the whole corpus, dedupe, check" to **per-line** extraction with a negation check:

- For each line (not each match) containing a backticked `` `fleet <cmd>` ``, check whether that
  same line also matches a small, fixed, case-insensitive negation-phrase set: `does/do not exist`,
  `is not a (real) command`, `not a real command`, `no such command`.
- If it matches, every command mentioned **on that line** is excluded from the check set for this
  run (counted separately as `excluded as truthfully-negated`), because the line is a truthful
  absent-claim, not a claim of capability.
- Otherwise the command is added to the positive claim set, deduped, and checked against the real
  binary exactly as before — **the predicate itself (`unknown command` from the real binary) is
  byte-for-byte unchanged.**
- Doing this **per line** rather than per corpus-wide command name matters: a command negated in
  one place is still checked if it is claimed positively anywhere else in the docs. The old
  corpus-wide `sort -u` could not express that distinction; this version can.

Deliberately NOT a general negation solver — a fixed phrase list, scoped to same-line context, per
the task brief's own instruction not to over-engineer this.

### 2. Mutation test — both directions, real binary, isolated fixtures (not the real docs tree)

Fixtures (not part of the repo; scratch-only, per B13/B16 precedent for detector mutation tests):

- `TRUE_POSITIVE.md`: `` This document describes fleet's capabilities. It supports `fleet
  definitelynotreal` for provisioning nodes. `` — an ordinary, non-negated false claim. Must still
  be CAUGHT.
- `TRUE_NEGATIVE.md`: two backticked mentions of `` `fleet arch` ``, each in a sentence that
  explicitly says it does not exist (`does NOT exist as a command`, `is not a command`) — the exact
  shape of B1's original false positive. Must NOT be caught.

Ran M6's real extraction/negation logic (copied verbatim from the fixed script) against these two
fixtures together, using the real built `fleet` binary as ground truth for "does this command
exist":

```
$ bash run.sh <repo-root> <fixture-dir>
M6-fixture: documented but missing: fleet definitelynotreal
M6-fixture: 0 of 1 checked commands exist (denominator: 1, excluded as truthfully-negated: 2)
$ echo $?
1
```

Both directions hold:
- The genuinely-missing command (`definitelynotreal`) is **still caught** (`BAD`, exit 1) — the
  negation fix does not blanket-suppress real catches.
- Both negated mentions of `fleet arch` are **excluded** (2 of them, matching the 2 lines in the
  fixture) rather than flagged, and correctly do not inflate the checked-commands denominator.

This is the mutation test the backlog explicitly asked for: *"a detector that learns to ignore
things is one edit from unfalsifiable"* — proven it still ignores only the negated case and still
fires on the un-negated one.
