# B3 — Detector for B1/B2 drift (`tests/corpus/M8.sh`)

## Expected

Coherence measured once (B1/B2's audit of `docs/BLUEPRINT-COHERENCE.md`) decays the moment a
command named as evidence for an `IMPLEMENTED` claim is renamed or removed and nobody re-reads the
audit doc. Add `tests/corpus/M8.sh`: every command cited as `IMPLEMENTED` in
`docs/BLUEPRINT-COHERENCE.md` must still exist in the built binary's dispatch surface.

## What the doc actually cites

`docs/BLUEPRINT-COHERENCE.md` does not use M6's `` `fleet <cmd>` `` backtick convention uniformly.
Most command citations in `IMPLEMENTED` rows are bare backticked words that read as CLI invocations
inside the evidence prose, e.g. "`` `sow` `` creates a ready record and exits 9" (06.2) and
"`` `ledger verify` `` prints equal checked/total counts" (04.4). Extracting every bare backticked
lowercase token blindly would false-positive on:

- Rust identifiers with underscores (`run_with_evidence`, `verifier_for`, `append_receipt`) —
  excluded by the extraction's `[a-z-]*` character class, which underscores don't match.
- JSON field names inside inline code (`` `seq` ``, from "requires `seq`, hashes, ...").
- POSIX primitives named in passing (`` `setsid` ``, `` `wait` ``, from 07.4's evidence prose),
  and the function name `` `main` ``.

I found these six specific false positives (`seq`, `setsid`, `wait`, `main`, `crew`, `keel`) by running the
extraction unfiltered against the current doc and reading every match by hand — not a general NLP
solver, the same "kept deliberately narrow" trade M6 made for its negation-phrase list. They are
excluded by a small `DENY_RE` in M8.sh, documented inline with exactly this reasoning.

The detector is also scoped to rows whose result column is literally `IMPLEMENTED`: a `PARTIAL` row
may legitimately name a command that doesn't fully work yet (`` `fleet impact` `` at 09.1 is
`PARTIAL`) and an `ABSENT` row names a command specifically because it's missing
(`` `recur` `` at 08.5, "No `recur` command ... exists") — holding those to "still exists" would be
wrong.

With both filters, the doc's current `IMPLEMENTED` denominator resolves to exactly 4 commands:
`sow`, `sow accept`, `ledger verify`, `route`. That is the published denominator M8.sh prints:

    M8: 4 of 4 IMPLEMENTED-cited commands still exist in the dispatch surface (denominator: 4)

## `FLEET_BIN` resolution — not repeating the earlier bug

M3/M9/M10/`install.sh` were each found this session to hardcode `$ROOT/keel/target/debug/fleet`,
which silently exit-77's (excluded, not checked) whenever the build lands in an external
`CARGO_TARGET_DIR` — the exact AGENTS.md-recommended worktree convention verify.sh itself computes
and exports. M8.sh uses the same override chain as the already-fixed M9 from the start:

    B="${FLEET_BIN:-${CARGO_TARGET_DIR:-$ROOT/keel/target}/debug/fleet}"

1. **`recur`/`semgrep`/`trivy`** fail with `bash: bin/recur-gate.sh: No such file or directory`

   `?? bin/trivy-gate.sh` in the git status this task started from) — never committed, so a fresh

   'recur|semgrep|trivy'` in this worktree returns nothing, and `git log --oneline -1 --
   bin/recur-gate.sh` returns nothing (no commit history for the file at all). Nothing this task
   touched created or deleted these files.
2. **`corpus`** fails with `caught=1`. Isolated by running `tests/corpus/run.sh` directly and then
   every detector individually: the sole catch is **`M2.sh`** ("16699 files in the tree (>15000).
   Build artifacts are almost certainly inside the repo") — because this task built the binary into
   the in-repo default `$ROOT/keel/target` (`cargo build -p fleet --bin fleet`, no
   `CARGO_TARGET_DIR` exported) rather than the AGENTS.md-mandated external shared cache. That is a
   build-location choice for this task's own verification run, not a code or detector defect; `M8`
   itself reports `4 of 4` inside that same corpus run (line `M8: 4 of 4 ...` appears once per
   corpus pass, `checked=37 total=37 caught=1` with M8 not among the caught set — confirmed by
   running every corpus detector standalone and finding `M2.sh` is the only one that exits 1).

None of the four failing stages are in files this task touched

## Verdict

`tests/corpus/M8.sh` exists, publishes a real denominator (4 of 4), is mutation-tested in both
directions against the live doc and binary (not asserted), and is registered in
`tests/corpus/MANIFEST.sha256` via `bin/detector-integrity.sh --update`. `FLEET_MUTANTS=0 bash

rounded up.
