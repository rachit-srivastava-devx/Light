## F-1 (P0) — `scan/BLUEPRINT.md` tells a builder to build in a directory it also forbids, and its size gate points at the empty tree

Three statements in one file, mutually exclusive:

| Line | Says |
|---|---|
| `scan/BLUEPRINT.md:25` (§4 "Crate/package layout") | ```crates/scan/{Cargo.toml,src/lib.rs,src/material.rs,src/types.rs,tests/material.rs}``` — a second `Cargo.toml` is a second crate |
| `scan/BLUEPRINT.md:30` | "`scan` is **NOT** a new crate … edit-in-place of the existing `crates/fleet-scan/`. **Do not create a separate `crates/scan/` directory.**" |
| `scan/BLUEPRINT.md:117` (§12 gate) | `find crates/scan -name '*.rs' -print0 \| xargs -0 wc -l` |

`NODE-MAP.md:17` sides with the forbidden reading: planned package `crates/scan`, evidence seam
`crates/fleet-scan`. It is the **only** one of the 32 NODE-MAP rows that contradicts its node's
crate-status line — `context`, `verify` and `store` all agree with theirs.

Two compounding harms, not one:

1. **Identity.** A 4B agent handed `scan` cannot tell which tree to touch. That is the AGENTS.md:66
   bar, and it is verbatim the rationale the previous review used to grade NEW-2 a P0 for
   `verify`/`context`/`store`. `scan` is worse: those three contradicted §7 across sections, `scan`
   contradicts itself inside §4 and again in §12.
2. **A gate that cannot fail.** Done correctly (edit-in-place), `find crates/scan` matches nothing,
   so the ≤80-line check passes on an empty set. The line also has no assertion at all — compare
   `planner:117`, which pipes the same `find` through `awk '$1>80 && $2!="total"'`. `scan:117` merely
   prints. This is `fleet/PRINCIPLES.md` verbatim: *a check cheaper to fake than to satisfy will be
   faked* — and the same defect class as the already-closed P1-7 ("clippy gate cannot fail").

`scan` is an authority node (`§13` — "mutation floor is ≥80% for this authority predicate"), so the
node most in need of a real file-size gate has a decorative one. §12's `cargo test -p fleet-scan` and
`cargo clippy -p fleet-scan` are correct — only the `find` and §4 are wrong, which is what makes this
cheap.

**Fix:** in `scan/BLUEPRINT.md` change `:25` to the `crates/fleet-scan/` paths and `:117` to
`find crates/fleet-scan -name '*.rs' -print0 | xargs -0 wc -l | awk '$1>80 && $2!="total"'`; in
`NODE-MAP.md:17` change the planned package to `crates/fleet-scan` (edit-in-place). Three edits.

## F-3 (P2) — `EDGE-TYPES.md:5` defines the owning-crate column in a way 9 of its own rows violate

The header gloss reads "Owning-crate = the crate's `name` field as used in `cargo test -p <name>`."
But rows `:9-10` (`fleet-types`), `:18-21` and `:22-25` (`fleet-scan`) name the crate that **defines
the type**, while their canonical tests live elsewhere — `:22`'s test is
`questions::tests::business_probe_output_merges`, which runs under `-p questions`, not
`-p fleet-scan`. The column's actual and correct meaning is *type owner*; the `-p` gloss is leftover
framing from the NEW-1 prefix fix. Low blast radius — the test-id column names its crate
unambiguously — but reword `:5` to "the crate that defines the payload type" and add "run the
canonical test under the crate named in its test id."
