## 3. N-1 executed, not read

The brief's fixture, plus six further cases I added because a gate that only passes its own
demo fixture is a proxy, not a property.

```
$ find /tmp/gate-test -name '*.rs' -exec awk '{c[FILENAME]++} END{for(f in c) if(c[f]>80){print f": "c[f]" lines"; bad=1} exit bad}' {} +
/tmp/gate-test/src/big.rs: 100 lines
exit: 1
```

| Case | Setup | Result | Verdict |
|---|---|---|---|
| Briefed fixture | `big.rs` 100 lines, `small.rs` 50 | prints `big.rs: 100 lines`, exit **1** | as expected |
| Clean tree | violator removed | no output, exit **0** | as expected |
| A — multiple violators | 100, 90, 10 lines | **both** violators printed, exit 1 | per-file counting confirmed; the old NR-total bug would have printed one aggregate |
| B — boundary `= 80` | one 80-line file | exit **0** | `>80` is the correct strict comparison; 80 is legal |
| C — boundary `= 81` | one 81-line file | exit **1** | off-by-one is correct at the edge |
| D — nested `tests/` | 200-line file under `tests/` | exit **1** | confirms site 5's widened denominator actually bites |
| E — vacuous | dir exists, zero `.rs` | exit **0** | see §5 residual R2 |
| F — missing dir | nonexistent path | `find` errors, exit **1** | fails loudly rather than passing silently |
| G — unterminated final line | 80 newlines + 81st line with no trailing `\n` | exit **1** (awk 81, `wc -l` 80) | awk is the *more* correct counter here |

The three mechanics named in the brief are confirmed by A, D, and the exit codes respectively:
`{} +` batches all files into one awk; `c[FILENAME]` keeps counts per file so concatenation cannot
produce the NR-total bug; `exit bad` propagates through `find`'s exit status. `bad` is unset on a
clean run, and `exit bad` with an unset variable exits 0 — which is why case B and the clean case
both return 0 rather than erroring.
