The one thing to remember

You talk or type a request. Fleet plans it in small, reviewed pieces, builds pieces in parallel, checks every piece twice, and asks you before anything leaves your machine. Nothing below changes that shape — it's the detail behind it.

00 · MARKET

This already has a market — others sell it today

The plan is a product, the same shape as a retail OS: one thing every dev team needs, sold as a seat. Six reference points, not a novel bet — from a human-in-the-loop IDE to fully autonomous engineers at billion-dollar valuations.

ReferenceWhat it isWhy it matters here
HumanLayerClosest shape to Fleet today: a QRSPI cycle (Questions → Research → Design → Structure → Plan → Implement) with a mandatory human checkpoint at every phaseProof the category sells now, at roughly $100/month per seat — but it stops at implement: no automated verify, gate, or merge step of its own
GVS5HNot a product — the Qwen team's own proof-of-concept for the self-orchestration technique Fleet's repair loop already benchmarks against (LLD-META-L8-ADDENDUM-2.md & -3.md)Per its authors, a 32B-parameter Qwen model outperformed Fable 5 on it — a data point on model choice, not on Fleet itself
Ara YCA closed loop, in its own words: suggest → act → learn → improve — background agents, persistent memory, reusable skillsThe closest full-loop match to Fleet's shape of all six — same suggest/build/learn cycle, same background-agent model as Phase 3
Factory (Droids)Droids handle plan → code → test → review → deploy → monitor, with engineers dialing autonomy per workflow$1.5B valuation, hundreds of thousands of daily users at NVIDIA, Adobe, EY — proof this sells at real enterprise scale, not just to solo devs
Cognition (Devin)Assign a task; Devin plans, writes, tests, and submits a PR with no intervention — the most autonomous of the sixCut its entry price from $500/seat to $20/seat in its 2.0 relaunch — the strongest signal yet that full autonomy is what the market will pay for

What ships, and how long it takes

Six build increments, in the order the design doc requires (each proves itself before the next starts). Time is agentic build time — how long a supervised agent fleet spends actually building and testing it, not human calendar time. All estimates, nothing measured yet.

#IncrementWhat shipsAgentic timeStatus
AAuthority + one adapterOne real CLI does one safe, isolated edit under a durable lease~8 agent-daysdone
BFull single-repo workflowAsk / review / small-change / feature all reach a merged, gated PR~18 agent-daysin progress
CBounded concurrencyTwo modules build in parallel with real resource limits~12 agent-daysproposed
DMemory + economicsLessons, pinned standards, cost tracking, retention pressure~14 agent-daysproposed
ELong runs + connectorsPause/resume, quota failover, GitHub/Gmail triggers, 72h soak~10 agent-daysproposed
FMulti-repo + optimizationOne logical change across repos; routing tunes itself within limits~12 agent-daysproposed
—Buffer, ~20%Unknowns every one of the above will hit~16 agent-daysproposed
—Total ~90 agent-days1 / 6 built, 1 in progress

"Agent-day" = one agent working continuously for a day, under human spot-checks — not a person's day. Several increments can overlap once their dependencies are proven.

04

How Fleet rolls out

Three phases of adoption, not to be confused with the six build increments above — those ship the software; these describe how far it's trusted with your org's work.

#PhaseWhat changesWhat you get
1Per-developer improvementRuns local to one developer; memory and standards stay on their machineFaster solo loop — less time lost to old problems, on that one machine
2Central DB + standards maintainedRepo Memory + Standards syncs across the team; one lesson benefits everyone, not just its authorThe team stops re-learning the same mistake; standards drift gets caught centrally
3Fleet moves to a serverThe background loop runs 24/7 on an always-on box, not a laptopFleet auto-picks up tech debt and assigned tickets on its own, no one has to kick it off

Phase 3 is what the $300–450/month "server / hosting" line in §06 pays for.

05

How we'll know it actually works

Three outcomes we're actually watching for — everything else below is how each build increment proves itself along the way.

OutcomeWhat Fleet does about itWhat we watch
Developers know more, own moreTeach-back explains every plan and PR; the knowledge base answers "why is this like this" instead of a colleagueRepeat-mistake rate; how often a senior engineer gets asked the same question twice
Execution gets fasterModules build in parallel; review starts with context already explained, not from scratchCycle time, open to merge; review minutes per PR
Fewer bugs reach productionA different model reviews every diff; tests + secret scan gate twice — before merge and afterEscaped-defect rate; days a bug survives before it's caught

And underneath those three: each build increment ships with its own pass/fail bar, from the design doc's own exit evidence, §23. No increment is "done" on a demo; it's done on the test.

#What we runPass bar
AOne real installed CLI does one read + one isolated editWorker never touches the ledger, credentials, or controller socket
BAll 5 request types run end to endA changed tree invalidates the verdict; nothing publishes without approval
CTwo builds fight for the same file on purposeCollision detected, one waits — no double-write, no deadlock
DFeed it a poisoned "lesson"It's refused; disk pressure never weakens a gate to make room
E72-hour soak: sleep, restart, quota loss, injected faultsRecovers within 30s; no event processed twice
FA multi-repo change fails halfwayRollback restores the exact prior state, not an approximation
06

What it costs, per month

Fleet itself is a harness, not a product — no license, no subscription. What costs money is the CLI agent it drives (Claude Code and similar), billed by that vendor per package, per user — plus, from Phase 3 on, a machine to keep it running.

Line itemWhat it actually isEst. $ / month
Fleet, the harnessOrchestration only — no fee of its own$0
CLI agent package, per developerBilled by the agent vendor, not Fleet — e.g. Claude Code Pro~$200
Heavier use / multiple lanesSame package, a higher seat tier or usage-based add-on$200–400
Always-on box (Phase 3)System requirement to run the background loop 24/7 — not a Fleet fee either$300–450

Estimate only — no billing data has been collected against this design yet, and package prices are the vendor's to change. §17 tracks real per-task cost once increment D ships; this table gets replaced with measured numbers then.
